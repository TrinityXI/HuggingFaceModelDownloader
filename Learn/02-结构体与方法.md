# 02 - 结构体与方法

从 HuggingFaceModelDownloader 学习 Go 的结构体设计

## 📝 本章目标

- 理解结构体的定义和使用
- 掌握方法的定义（值接收者 vs 指针接收者）
- 学习结构体的嵌入和组合
- 理解结构体标签的作用

## 1. 结构体基础

### 1.1 结构体定义

**项目中的例子** (`hfdownloader/types.go` 第 5-11 行)：

```go
type Job struct {
	Repo               string
	IsDataset          bool
	Revision           string
	Filters            []string
	AppendFilterSubdir bool
}
```

**语法格式：**

```go
type 结构体名 struct {
	字段名1 类型1
	字段名2 类型2
	// ...
}
```

### 1.2 结构体实例化

**方式一：字面量初始化** (`main.go` 中隐式使用)：

```go
job := hfdownloader.Job{
	Repo:      "owner/name",
	Revision:  "main",
	IsDataset: false,
}
```

**方式二：零值初始化**：

```go
var job hfdownloader.Job  // 所有字段为零值
```

**方式三：部分字段初始化**：

```go
job := hfdownloader.Job{
	Repo: "owner/name",
	// 其他字段使用零值
}
```

**方式四：使用 new**：

```go
job := new(hfdownloader.Job)  // 返回 *Job 指针
```

### 1.3 访问结构体字段

```go
// 读取
repo := job.Repo

// 修改
job.Revision = "v1.0.0"

// 指针自动解引用
jobPtr := &job
jobPtr.Repo = "new/name"  // 等价于 (*jobPtr).Repo
```

## 2. Settings 结构体分析

**完整定义** (`hfdownloader/types.go` 第 12-28 行)：

```go
type Settings struct {
	OutputDir          string
	Concurrency        int
	MaxActiveDownloads int
	MultipartThreshold string
	Verify             string
	Retries            int
	BackoffInitial     string
	BackoffMax         string
	Token              string
	// Endpoint is the base URL for HuggingFace API (default: https://huggingface.co)
	Endpoint string
	// MirrorEndpoint is the fallback mirror URL (e.g., https://hf-mirror.com)
	MirrorEndpoint string
	// UseMirrorOnFailure enables automatic fallback to mirror on primary failure
	UseMirrorOnFailure bool

```

**设计要点：**

1. **明确的字段名**：`OutputDir`、`Concurrency` 等一目了然
2. **合理的类型选择**：
   - `string` 用于路径和 URL
   - `int` 用于计数器
   - `bool` 用于开关选项
3. **字段注释**：解释复杂字段的含义

## 3. 方法定义

### 3.1 方法 vs 函数

**函数**：独立的代码块

```go
func IsValidModelName(modelName string) bool {
	return strings.Contains(modelName, "/")
}
```

**方法**：附加到类型上的函数

```go
func (j *Job) IsValid() bool {
	return j.Repo != ""
}
```

### 3.2 值接收者

```go
type Point struct {
	X, Y int
}

// 值接收者：接收结构体的副本
func (p Point) Distance() float64 {
	return math.Sqrt(float64(p.X*p.X + p.Y*p.Y))
}

// 调用
p := Point{X: 3, Y: 4}
dist := p.Distance()  // 5.0
```

**特点：**
- ✅ 不会修改原始结构体
- ✅ 适合小型结构体
- ❌ 大型结构体会有性能损失（拷贝）

### 3.3 指针接收者

```go
type Counter struct {
	count int
}

// 指针接收者：可以修改结构体
func (c *Counter) Increment() {
	c.count++
}

func (c *Counter) Value() int {
	return c.count
}

// 调用
c := &Counter{}
c.Increment()  // count = 1
c.Increment()  // count = 2
fmt.Println(c.Value())  // 2
```

**特点：**
- ✅ 可以修改结构体字段
- ✅ 避免拷贝，性能更好
- ✅ 大型结构体首选

### 3.4 项目中的方法示例

虽然项目主要使用函数，但我们可以看到类似的模式：

```go
// 在 hfdownloader/downloader.go 中定义的函数
// 可以理解为隐式的 "方法"

func IsValidModelName(modelName string) bool {
	if modelName == "" || !strings.Contains(modelName, "/") {
		return false
	}
	parts := strings.Split(modelName, "/")
	return len(parts) == 2 && parts[0] != "" && parts[1] != ""
}
```

**如果改写成方法：**

```go
func (j Job) IsValidRepo() bool {
	if j.Repo == "" || !strings.Contains(j.Repo, "/") {
		return false
	}
	parts := strings.Split(j.Repo, "/")
	return len(parts) == 2 && parts[0] != "" && parts[1] != ""
}

// 使用
if job.IsValidRepo() {
	// ...
}
```

## 5. 结构体标签

### 5.1 JSON 标签

**项目示例** (`hfdownloader/types.go` 第 30-38 行)：

```go
type ProgressEvent struct {
	Time     time.Time `json:"time"`
	Level    string    `json:"level,omitempty"`
	Event    string    `json:"event"`
	Repo     string    `json:"repo,omitempty"`
	Revision string    `json:"revision,omitempty"`
	Path     string    `json:"path,omitempty"`
	Bytes    int64     `json:"bytes,omitempty"`
	Total    int64     `json:"total,omitempty"`
	Attempt  int       `json:"attempt,omitempty"`
	Message  string    `json:"message,omitempty"`
}
```

**标签说明：**

- `json:"time"` - JSON 字段名为 "time"
- `json:"level,omitempty"` - 如果字段为空值，则不输出到 JSON

**序列化示例：**

```go
import "encoding/json"

event := ProgressEvent{
	Time:  time.Now(),
	Event: "file_done",
	Path:  "model.bin",
}

data, _ := json.Marshal(event)
fmt.Println(string(data))
// 输出: {"time":"2025-11-19T14:00:00Z","event":"file_done","path":"model.bin"}
```

### 5.2 其他常见标签

```go
type User struct {
	ID       int    `json:"id" db:"user_id" xml:"id"`
	Username string `json:"username" db:"username" validate:"required"`
	Email    string `json:"email,omitempty" db:"email" validate:"email"`
}
```

**标签类型：**
- `json` - JSON 序列化
- `xml` - XML 序列化
- `db` - 数据库字段映射
- `validate` - 验证规则
- `yaml` - YAML 序列化

## 6. 结构体比较

### 6.1 可比较的结构体

```go
type Point struct {
	X, Y int
}

p1 := Point{1, 2}
p2 := Point{1, 2}
p3 := Point{2, 3}

fmt.Println(p1 == p2)  // true
fmt.Println(p1 == p3)  // false
```

### 6.2 不可比较的结构体

包含切片、map 或函数的结构体不能直接比较：

```go
type Config struct {
	Name    string
	Options []string  // 切片不可比较
}

// c1 == c2  // 编译错误！
```

**解决方案：使用 reflect.DeepEqual**

```go
import "reflect"

c1 := Config{Name: "test", Options: []string{"a"}}
c2 := Config{Name: "test", Options: []string{"a"}}

fmt.Println(reflect.DeepEqual(c1, c2))  // true
```

## 7. 结构体的内存布局

### 7.1 字段对齐

Go 编译器会对结构体字段进行对齐以提高性能：

```go
// 不好的布局
type Bad struct {
	A bool   // 1 byte + 7 bytes padding
	B int64  // 8 bytes
	C bool   // 1 byte + 7 bytes padding
	D int64  // 8 bytes
}  // 总共 32 bytes

// 好的布局
type Good struct {
	B int64  // 8 bytes
	D int64  // 8 bytes
	A bool   // 1 byte
	C bool   // 1 byte + 6 bytes padding
}  // 总共 24 bytes
```

### 7.2 查看结构体大小

```go
import "unsafe"

fmt.Println(unsafe.Sizeof(Job{}))      // 打印 Job 的大小
fmt.Println(unsafe.Sizeof(Settings{}))  // 打印 Settings 的大小
```

## 8. 构造函数模式

Go 没有构造函数，但可以使用工厂函数：

### 8.1 New 函数

```go
func NewJob(repo string) *Job {
	return &Job{
		Repo:     repo,
		Revision: "main",  // 默认值
	}
}

// 使用
job := NewJob("owner/name")
```

### 8.2 配置选项模式

```go
type JobOption func(*Job)

func WithRevision(rev string) JobOption {
	return func(j *Job) {
		j.Revision = rev
	}
}

func WithFilters(filters []string) JobOption {
	return func(j *Job) {
		j.Filters = filters
	}
}

func NewJob(repo string, opts ...JobOption) *Job {
	job := &Job{
		Repo:     repo,
		Revision: "main",
	}
	for _, opt := range opts {
		opt(job)
	}
	return job
}

// 使用
job := NewJob("owner/name",
	WithRevision("v1.0.0"),
	WithFilters([]string{"q4_0"}),
)
```

## 11. 最佳实践

### 11.1 何时使用指针接收者

**使用指针接收者的情况：**
- 方法需要修改接收者
- 接收者是大型结构体
- 希望保持一致性（如果一个方法是指针接收者，其他也应该是）

### 11.2 结构体设计原则

1. **单一职责**：一个结构体只做一件事
2. **字段少而精**：避免过多字段
3. **导出必要字段**：首字母大写的字段可被外部访问
4. **使用有意义的名称**：`OutputDir` 比 `ODir` 好
5. **添加注释**：复杂字段需要注释说明

### 11.3 零值可用性

设计结构体时，考虑零值是否可用：

```go
// 好的设计
type Buffer struct {
	data []byte  // nil 切片是可用的
}

func (b *Buffer) Write(p []byte) {
	b.data = append(b.data, p...)  // nil 切片可以 append
}

// 使用
var buf Buffer  // 零值可用
buf.Write([]byte("hello"))
```
