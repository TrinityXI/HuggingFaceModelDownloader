## 1. Go 的错误处理哲学

### 1.1 显式错误处理

Go 不使用异常（try-catch），而是将错误作为返回值：

```go
// ❌ 其他语言（Java/Python）
try {
    result = doSomething()
} catch (Exception e) {
    handle(e)
}

// ✅ Go 风格
result, err := doSomething()
if err != nil {
    // 处理错误
}
```

**优点：**
- 错误处理逻辑清晰可见
- 强制开发者考虑错误情况
- 没有隐式的控制流

### 1.2 error 接口

```go
type error interface {
    Error() string
}
```

任何实现了 `Error() string` 方法的类型都是 error。

**项目中的例子** (`hfdownloader/downloader.go` 第 345 行)：

**基本用法：**

```go
import "errors"

func divide(a, b int) (int, error) {

	}
	return a / b, nil
}

```

### 2.3 自定义错误类型

```go
type ValidationError struct {
	Field string
	Value string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("invalid %s: %s", e.Field, e.Value)
}

// 使用
func validate(email string) error {
	if !strings.Contains(email, "@") {
		return &ValidationError{
			Field: "email",
			Value: email,
		}
	}
	return nil
}
```

## 4. 错误包装

### 4.1 使用 %w 包装错误

**项目中的例子** (`hfdownloader/downloader.go` 第 178 行)：

```go
return fmt.Errorf("both primary (%s) and mirror (%s) failed: %w", 
	originalEndpoint, cfg.MirrorEndpoint, err)
```

**完整示例：**

```go
func readConfig(filename string) error {
	data, err := os.ReadFile(filename)
	if err != nil {
		// 包装错误，添加上下文
		return fmt.Errorf("read config: %w", err)
	}
	
	if err := json.Unmarshal(data, &config); err != nil {
		return fmt.Errorf("parse config: %w", err)
	}
	
	return nil
}
```

### 4.2 errors.Is（检查特定错误）

```go
import "errors"

var ErrNotFound = errors.New("not found")

func findUser(id int) error {
	// ...
	return ErrNotFound
}

// 使用
if err := findUser(123); err != nil {
	if errors.Is(err, ErrNotFound) {
		// 特定处理
		log.Println("User not found")
	} else {
		// 其他错误
		log.Printf("Error: %v", err)
	}
}
```

### 4.3 errors.As（类型断言）

```go
type NetworkError struct {
	Code int
	Msg  string
}

func (e *NetworkError) Error() string {
	return fmt.Sprintf("network error %d: %s", e.Code, e.Msg)
}

// 使用
var netErr *NetworkError
if errors.As(err, &netErr) {
	log.Printf("Network error code: %d", netErr.Code)
}
```

### 5.3 链式错误处理

**镜像切换逻辑** (`hfdownloader/downloader.go` 第 165-187 行)：

```go
plan, err := scanRepo(ctx, httpc, cfg.Token, job, cfg)
if err != nil {
	// 尝试镜像
	if cfg.UseMirrorOnFailure && cfg.MirrorEndpoint != "" {
		emit(ProgressEvent{
			Event:   "info",
			Message: fmt.Sprintf("primary endpoint failed (%v), trying mirror: %s", err, cfg.MirrorEndpoint),
		})
		
		originalEndpoint := cfg.Endpoint
		cfg.Endpoint = cfg.MirrorEndpoint
		plan, err = scanRepo(ctx, httpc, cfg.Token, job, cfg)
		
		if err != nil {
			// 两个都失败，返回详细错误
			return fmt.Errorf("both primary (%s) and mirror (%s) failed: %w", 
				originalEndpoint, cfg.MirrorEndpoint, err)
		}
		
		emit(ProgressEvent{
			Event:   "info",
			Message: "using mirror endpoint for download",
		})
	} else {
		return err
	}
}
```

**模式特点：**
- 尝试降级策略
- 记录尝试过程
- 提供详细的失败信息

## 6. 错误处理最佳实践

### 6.1 不要忽略错误

**❌ 错误：**

```go
data, _ := os.ReadFile("config.json")  // 忽略错误
```

**✅ 正确：**

```go
data, err := os.ReadFile("config.json")
if err != nil {
	log.Fatalf("Failed to read config: %v", err)
}
```

### 6.2 只处理一次错误

**❌ 错误：**

```go
if err != nil {
	log.Printf("Error: %v", err)  // 记录
	return err                     // 返回
}
// 调用者也会记录，导致重复
```

**✅ 正确：**

```go
// 方式 1: 只记录
if err != nil {
	log.Printf("Error: %v", err)
	return nil  // 或处理后返回 nil
}

// 方式 2: 只返回
if err != nil {
	return fmt.Errorf("operation failed: %w", err)
}
```

### 6.3 添加上下文信息

**❌ 错误：**

```go
func processFile(filename string) error {
	data, err := os.ReadFile(filename)
	if err != nil {
		return err  // 丢失了上下文
	}
	// ...
}
```

**✅ 正确：**

```go
func processFile(filename string) error {
	data, err := os.ReadFile(filename)
	if err != nil {
		return fmt.Errorf("process file %s: %w", filename, err)
	}
	// ...
}
```

### 6.4 使用哨兵错误

```go
var (
	ErrNotFound    = errors.New("not found")
	ErrUnauthorized = errors.New("unauthorized")
	ErrInvalidInput = errors.New("invalid input")
)

func getUser(id int) (*User, error) {
	if id < 0 {
		return nil, ErrInvalidInput
	}
	// ...
	return nil, ErrNotFound
}

// 使用
user, err := getUser(123)
if errors.Is(err, ErrNotFound) {
	// 特定处理
}
```

## 7. Panic 和 Recover

### 7.1 何时使用 Panic

Panic 应该只用于**不可恢复的错误**：

```go
// ✅ 合理使用
func mustConnect() *DB {
	db, err := connect()
	if err != nil {
		panic(fmt.Sprintf("cannot connect to database: %v", err))
	}
	return db
}

// ❌ 不推荐
func divide(a, b int) int {
	if b == 0 {
		panic("division by zero")  // 应该返回 error
	}
	return a / b
}
```

### 7.2 Defer 和 Panic

**项目中的 defer 使用** (`hfdownloader/downloader.go`)：

```go
defer resp.Body.Close()
defer wg.Done()
defer func() { <-lim }()
```

**Recover 示例：**

```go
func safeExecute(fn func()) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("panic recovered: %v", r)
		}
	}()
	
	fn()
	return nil
}

// 使用
err := safeExecute(func() {
	// 可能 panic 的代码
	panic("something went wrong")
})
if err != nil {
	log.Printf("Recovered from panic: %v", err)
}
```

## 8. 并发中的错误处理

### 8.1 错误 Channel

**项目中的例子** (`hfdownloader/downloader.go` 第 180 行)：

```go
errCh := make(chan error, len(plan.Items))

go func() {
	if err := downloadFile(); err != nil {
		select {
		case errCh <- err:
		default:  // channel 满了就丢弃
		}
	}
}()

// 收集错误
select {
case err := <-errCh:
	if err != nil {
		// 处理错误
	}
default:
}
```

### 8.2 errgroup 包

```go
import "golang.org/x/sync/errgroup"

func downloadFiles(urls []string) error {
	g := new(errgroup.Group)
	
	for _, url := range urls {
		url := url  // 捕获循环变量
		g.Go(func() error {
			return downloadFile(url)
		})
	}
	
	// 等待所有 goroutine 完成，返回第一个错误
	return g.Wait()
}
```

## 11. 调试错误

### 11.1 打印详细错误

```go
if err != nil {
	log.Printf("Error: %v", err)      // 简单信息
	log.Printf("Error: %+v", err)     // 详细信息（某些类型）
	log.Printf("Error: %#v", err)     // Go 语法表示
}
```

### 11.2 错误栈跟踪

使用 `github.com/pkg/errors`：

```go
import "github.com/pkg/errors"

func doSomething() error {
	if err := operation(); err != nil {
		return errors.Wrap(err, "operation failed")
	}
	return nil
}

// 打印栈跟踪
err := doSomething()
if err != nil {
	fmt.Printf("%+v\n", err)  // 包含栈跟踪
}
```
